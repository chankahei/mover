SMT Solver Guardrail

A FastAPI service that checks whether LLM-generated content is logically consistent with its source material and optional hand-authored business rules, by compiling natural-language claims into a strongly-typed description-logic IR and discharging them with the Z3 SMT solver.

Topic & goal

The project answers one question:

"An LLM generated some text. Is it logically consistent with the source material it was supposed to be faithful to, and not violating optional business rules?"

The problem

In the case of an LLM generating a stock-news article. Is it faithful to the source data and compliant with policy?

  • Factual drift — the article says revenue is HK$5.0bn; the filing says HK$4.5bn.
  • Policy breach — the article issues a "STRONG BUY" a compliance rule forbids.

We want a guardrail that answers two questions precisely:

  • Is the input logically consistent with the grounding + rules?
  • If not, which exact sentences conflict, and why?

Core idea

The LLM translates; the solver decides.

LLM does the fuzzy part

Reads messy natural language and lowers each sentence into a small, strongly-typed logical form, the Intermediate Representation (IR).

Z3 does the rigorous part

Given the typed symbols, the Satisfiability Modulo Theories(SMT) solver proves whether they(Input, Grounding, and Manual_logic) can all hold at once -> if they can, the text is consistent; if not, it's inconsistent.

Z3 is an open-source SMT solver from Microsoft Research — source: github.com/Z3Prover/z3

The pipeline

A solver can't read Natural Language — so we translate both stories into the same tidy facts, then let it check if they can all be true.

LLM language model  ·  Z3 the solver  ·  CODE plain orchestration

①
Agree on a shared dictionary LLM (signature) — fix the exact words to use, so both texts say revenue_of(acme) instead of "sales" in one and "revenue" in the other.
Two sentences can only be compared if they use the same word.
②
Rewrite each sentence as one tidy fact LLM (claim) — "Q2 revenue was $5 billion" becomes revenue_of(acme) = 5.0.
The solver understands tidy facts, not prose.
③
Put every fact in one pile CODE (union) — the article's facts + the source's facts + the rules, all together.
Facts can only clash if they sit in the same place.
④
Sanity-check the facts CODE (type-check) — reject nonsense like revenue = "blue" with a clear error.
Catch mistakes early instead of confusing the solver later.
⑤
Hand the facts to the solver CODE Z3 (compile → Z3) — translate them into its language, tagging each so we can point back to the original sentence.
The solver does the rigorous logic we can't reliably do by eye.
⑥
Ask: can all the facts be true at once? Z3 (solve) — the solver answers SAT → consistent, UNSAT → inconsistent , or Unkown → reported honestly.
That SAT/UNSAT/Unkown is exactly the question we set out to answer.
⑦
Show the smallest clash(Minimal core), in natural language Z3 LLM (core + explanation) — pick out just the few sentences that are actually mutually contradicted, and say why.
"inconsistent" is useless; "these two revenue figures disagree" is actionable.

Pillar 1 — the shared signature

A contradiction is only detectable if both extractions use the same symbol.

Without it

input: ceo_is_john
grounding: chief_exec_is_jane

Disjoint vocabularies → never collide → miss.

With it

both → ceo_of(company)

One symbol, two values → clean contradiction.

So extraction is two-stage: first read both documents AND the manual rules to mint one canonical signature; then extract claims constrained to it (no inventing symbols).

Pillar 2 — the type system

One uninterpreted sort Entity for all individuals. On top of it:

ConstructZ3 shapeBuys you
ConceptEntity → Boolunary class, e.g. gives_advice(x)
RoleEntity × Entity → Boolbinary relation, e.g. listed_on(a,b)
AttributeEntity → Vfunctionality is free
EnumEnumSortclean closed-set contradictions

Because attributes are functions, revenue(acme)=5 ∧ revenue(acme)=4.5 is UNSAT for free — no extra axioms. Equality is split by sort (compare / enum_eq / func_eq / equal) so the LLM can't conflate categories.

From "UNSAT" to a useful answer

  • Claim tracking — each claim is asserted under a tracking literal named by its id, so Z3's unsat_core() hands back exactly which claim ids clash.
  • Minimal Unsatisfiable Subset(MUS) minimization — Z3's raw core can carry passengers; a deletion loop drops every non-essential claim, leaving a locally minimal core where every member is necessary. No innocent sentence is blamed.
  • Iterate — drop a core member and re-check to surface multiple independent conflicts (factual + policy in one run).
  • Explain — a deterministic renderer is the source of truth; an LLM optionally paraphrases the already-proven core (never adds facts).

Test Case 1 — Factual Drift

input_content: "Shares of SinoGreen Energy Group Limited (09876) climbed 2% today after the company reported a first-half net profit of HK$3.1 billion, up from HK$2.5 billion a year earlier. Revenue rose 24% year-on-year to HK$10.1 billion, driven by strong demand in the renewable sector. The board declared an interim dividend of HK$0.25 per share and reaffirmed its full-year guidance."

grounding_content: "In its official announcement, SinoGreen Energy Group Limited (09876) reported a first-half net profit of HK$2.4 billion, compared with HK$2.5 billion in the same period last year. Revenue increased 24% to HK$10.1 billion, driven by strong demand in the renewable sector. The board declared an interim dividend of HK$0.25 per share and maintained its full-year guidance."

manual_logic: "Disclosed financial figures must match the company's audited or announced results; any discrepancy constitutes misleading information in breach of SFC Code of Conduct para 16.5 and SFO Part XIV market misconduct provisions."
